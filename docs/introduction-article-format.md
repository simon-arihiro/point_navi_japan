# 紹介記事 デザイン仕様書（v1 ベースライン）

各サービスの「紹介記事」を、専門サイトとして統一感のあるフォーマット・トーンで提供するための仕様書。
本ドキュメントは今後の打ち合わせをもとに更新していく「生きた仕様書」。更新時は実装（`src/lib/ai/prompts.ts` の
`buildIntroductionArticlePrompt` / `SYSTEM_PROMPT_BASE`）にも反映すること。

関連記事（ガイド・FAQ・比較・キャンペーン・収益実績など）は本仕様の対象外。管理画面で入力したプロンプト・
参考URL・添付画像をもとにAIが自由に構成・執筆する（型を固定しない）。

---

## 1. URL・SEO

- 紹介記事は単独のURLを持たず、**サービス詳細ページ `/services/{category-slug}/{service-slug}` に統合表示**する
  - サービスのslugを含むため検索エンジンに評価されやすいURL構造になっている
  - 1サービス＝1紹介記事＝1URLという1:1の対応を維持する
- メタデータ
  - `<title>` = サービス名（`generateMetadata` で `services.name` を使用）
  - `description` = `services.description`（紹介記事生成時に自動更新）

## 2. ページ内レイアウト（上から順）

1. Basic Info カード：ロゴ / サービス名 / カテゴリタグ / 概要 / 公式サイトリンク
2. **紹介記事本文**（白カード内に Markdown → HTML で表示）
3. 関連記事一覧（同サービスの関連記事カード、最大6件）

サイドバー：Conversion Area（紹介コード・紹介リンク） / 公式サイトへのリンク

## 3. ビジュアルスタイル

`src/lib/markdown.ts` の `ARTICLE_PROSE_CLASS`（サイト共通の琥珀×ネイビー基調）に従う。

- 見出し：`font-black text-slate-900`
- リンク：`text-amber-700`、ホバーで下線
- 強調（`**太字**`）：`text-slate-900`
- 引用：`border-amber-300`
- 画像：角丸（`rounded-xl`）

紹介記事専用の追加スタイル・コンポーネント（評価バッジ、比較表、キャンペーン強調枠など）は **現状なし**。

## 4. 見出し構成（全サービス共通・厳守）

AIには下記の見出し（`##`）の文言・絵文字・順番・レベルを一字一句変えずに使わせる。タイトル（`#`）は出力しない。

| 順 | 見出し | 内容の目安 | 文字数目安 |
|---|---|---|---|
| 1 | `## 📝 {サービス名}とはどんなサービス？` | 運営会社・基本概要・どんな人におすすめか | 250〜350字 |
| 2 | `## 💬 実際に使ってみた感想` | 個人ブロガー視点の体験談 | 500〜700字 |
| 3 | `## ✅ メリット` | 箇条書き3〜5個（各1〜2文・具体的に） | — |
| 4 | `## ⚠️ デメリット・注意点` | 箇条書き2〜3個（各1〜2文・具体的に） | — |
| 5 | `## 🚀 登録方法・始め方` | 番号付き3〜5ステップ。紹介コード/リンクがあれば最終ステップで案内 | 300〜450字 |
| 6 | `## 📌 まとめ` | 総括とおすすめ度 | 150〜250字 |

全体の目安：2000〜3000字。箇条書きは `- `、番号付きリストは `1. ` の半角形式。

## 5. 文体・トーン規範

- 個人ブロガーの体験談風。口語的・親しみやすく温かみのある表現
- 禁止：公式宣伝語気、過度に丁寧な企業PRスタイル
- 「実際に使ってみた」「正直なところ」「これは本当におすすめ」等のフレーズを自然に散りばめる
- 出力言語：日本語のみ
