# 記事品質チェックスキル（point_navi_japan）

招待コード記事・レビュー記事などAI生成コンテンツをレビュー・リライトする際の基準。

## 必須チェック項目

1. **画像Markdownの構文崩れ**
   - `![alt](url)` が改行を挟んで分断されていないか（`![alt]\n(url)` や間に余計な文字が入る形）
   - 崩れている場合は `repairBrokenImageMarkdown()`（`src/lib/markdown.ts`）と同じパターンを意識して1行に修復する

2. **空疎な体験談断言の禁止・削減**
   - 「実際に利用した経験から」「実情として」「実利を伴う選択肢です」のような、具体性のない断定的フレーズの**繰り返し**は減点対象
   - 同じフレーズが記事内に2回以上出てきたら必ず指摘・修正する

3. **具体的な体験データの有無**
   - 利用期間（例: 2週間）、頻度・量（例: 1日6000〜8000歩）、実際に得たポイント・交換結果など、検証可能な体感情報があるか
   - ない場合は妥当な範囲で具体的な数字を補う（誇張・虚偽の効果断言は避ける）

4. **招待コード記事特有の情報密度**
   - 招待コードそのもの、適用タイミング（新規登録時のみ等）、反映タイムラグ、一人一回限り等の制約が明記されているか
   - 同じサービスの「体験談/レビュー」記事と内容が重複しすぎていないか（重複度が高いと低品質コンテンツと判定されるリスク）

5. **見出し構成の一貫性**
   - 既存記事群の絵文字付き見出しパターン（🎁 📋 💰 ⚠️ 📌 など）との整合性

## SEO順位が低い記事を調査する時の進め方

1. GSCで該当クエリの impressions / position / clicks を確認する（`/admin/seo` ページ参照）
2. 同カテゴリで順位が良い記事（比較対象）と本文を並べて、上記チェック項目の差分を洗い出す
3. impressions が極端に少ない（数件程度）場合は統計的have意味が薄いことも明示し、過度な大改修より軽微な改善＋様子見を提案する

## 制約

- このサンドボックス環境からは Supabase DB・本番サイトへの直接アクセスができないため、記事本文はユーザーに貼ってもらう必要がある
- 改善後のMarkdownはそのまま管理画面に貼り戻せる形で提示する
