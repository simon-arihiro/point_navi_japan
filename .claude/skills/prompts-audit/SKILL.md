# AIプロンプト監査スキル（point_navi_japan）

`src/lib/ai/prompts.ts` を改修する際の方針。

## 基本方針

- 記事のコンテンツ自体（DB上の既存記事）を直接いじるのではなく、**今後の生成・リライトで同じ不具合が再発しないように、プロンプトの指示文を強化する**のがこのスキルの目的
- 既知の不具合パターンが見つかったら、対応するコード側の自動修復（例: `repairBrokenImageMarkdown()`）と、プロンプト側の予防指示の両方を検討する（どちらか一方だけでは再発しやすい）

## 過去に発見・対処した不具合パターン（再発防止の参考）

1. **画像Markdownの改行分断**
   - 症状: `![alt]` と `(url)` の間で改行、または余計な文字列が挟まる
   - 対処: `【添付画像】` 指示文に「`![説明](画像URL)` は必ず改行を挟まず1行で書き、`]` と `(` の間に余計な文字や改行を入れないこと」を明記
   - リライト時の画像指示（`buildRewritePrompt` 周辺）にも同様の注意書きを入れる

2. **招待コード記事の空疎な体験談断言の多用**
   - 症状: 「実際に利用した経験から」等の同一フレーズを記事内で繰り返す、具体性のない断定
   - 対処方針: プロンプトに「同じ言い回しの体験談的断言を繰り返さない」「利用期間・頻度・実際の交換結果など具体的な数字を1〜2箇所含める」といった指示を追加することを検討

## 改修フロー

1. 不具合パターンを特定する（ユーザーが貼った実際の生成結果から）
2. `prompts.ts` 内の該当する指示ブロックを特定し、最小限の追記で予防指示を加える（既存の指示文の大幅な書き換えは避ける）
3. 可能であれば、同種の不具合に対するコード側のセーフティネット（`src/lib/markdown.ts` のユーティリティ等）が既にあるか確認し、なければ追加を検討する
4. `npx tsc --noEmit` と `npx eslint` で確認してから commit

## 注意

- このサンドボックスから本番のAI生成APIを実際に叩いて検証することはできない（ネットワーク制約）。効果検証はユーザーに実際の生成結果で確認してもらう
